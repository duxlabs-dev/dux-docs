Dux Files ships a flake with a package, a NixOS module and a home-manager module. Both modules expose the same `programs.dux-files` options; the home-manager module adds `settings`.

## Installation

### 1. Add the Flake Input

Add the Dux Files flake to your `flake.nix`:

```nix title="flake.nix"
{
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";

    dfiles = {
      url = "github:duxlabs-dev/dux-files";
      inputs.nixpkgs.follows = "nixpkgs";
    };
  };
}
```

### 2. Import a Module

For a per-user install, import the home-manager module:

```nix
imports = [
  inputs.dfiles.homeModules.dux-files
];
```

For a system-wide install, import the NixOS module instead:

```nix
imports = [
  inputs.dfiles.nixosModules.dux-files
];
```

`homeModules.default` and `nixosModules.default` are aliases.

### 3. Enable Dux Files

```nix
programs.dux-files.enable = true;
```

Rebuild and Dux Files is installed with its dux-qt-base runtime built in, the desktop entry and the `FileManager1` activation file. No separate Quickshell package is needed.

## Configuration Options

```nix
programs.dux-files = {
  enable = true;

  # Use a custom package (optional)
  package = inputs.dfiles.packages.${pkgs.stdenv.hostPlatform.system}.default;

  # Override the dux-qt-base runtime library built into the package (optional,
  # needs a dux-qt-base flake input that follows your nixpkgs; defaults to
  # the one Dux Files pins, built against your nixpkgs)
  duxQtBase.package = inputs.dux-qt-base.packages.${pkgs.stdenv.hostPlatform.system}.dux-qt-base;

  # Keep a resident instance so windows open fast and the portal answers at once
  systemd = {
    enable = true;
    target = "graphical-session.target";
    restartIfChanged = true;
  };

  # Serve other apps' open and save dialogs
  portal = {
    enable = true;      # register the dfiles backend with xdg-desktop-portal
    preferred = true;   # prefer it for org.freedesktop.impl.portal.FileChooser
    desktop = "niri";   # which xdg.portal.config entry gets the preference, "common" by default
  };
};
```

| Option | Default | What it does |
| --- | --- | --- |
| `package` | the flake package, built against `duxQtBase.package` | The Dux Files package to install |
| `duxQtBase.package` | the flake's `dux-qt-base` input, built against your nixpkgs | The dux-qt-base library embedded in the default `package` to run the UI |
| `systemd.enable` | `false` | Installs and enables the `dfiles` user service |
| `systemd.target` | `graphical-session.target` | The target the service follows. The home-manager module defaults it to `wayland.systemd.target` |
| `systemd.restartIfChanged` | `true` | Restart the service when the package changes (NixOS module) |
| `portal.enable` | `false` | Adds the package to `xdg.portal.extraPortals` so the `dfiles` backend is registered |
| `portal.preferred` | `false` | Writes `dfiles` into `xdg.portal.config.<desktop>."org.freedesktop.impl.portal.FileChooser"` |
| `portal.desktop` | `"common"` | Which portal configuration gets the preference: a lowercased `XDG_CURRENT_DESKTOP` name, or `common` |

The old `quickshell.package` option is removed; evaluation fails with a message pointing to `duxQtBase.package`.

See [Open and save dialogs](desktop-integration#open-and-save-dialogs) for what the portal backend does and which apps use it.

### UI Settings (home-manager)

The home-manager module can write the UI settings file for you. Keys match the [Settings](settings) page and land in `~/.config/dfiles/ui-settings.json`:

```nix
programs.dux-files = {
  enable = true;
  settings = {
    themeMode = "dark";
    radiusStrength = 50;
    defaultView = "list";
    vimKeys = true;
  };
};
```

:::warning[Settings become read-only]

A managed settings file is read-only, so changes made in the app's Settings page do not persist across rebuilds. Leave `settings` empty if you prefer to configure Dux Files from its UI.

:::

## Binary Cache

dux-qt-base, the Quickshell runtime built into Dux Files, takes a while to build from source. CI publishes `x86_64-linux` and `aarch64-linux` builds of every commit on `master` to `nix-cache.duxlabs.dev`, built against the latest `nixos-unstable` and `nixos-26.05` channel commits. Releases up to 2.1 use Quickshell from nixpkgs and don't need the cache.

Add the cache to your NixOS configuration:

```nix
nix.settings = {
  extra-substituters = [ "https://nix-cache.duxlabs.dev" ];
  extra-trusted-public-keys = [ "dux-1:lrBykuzHKu9F6WsCbK83C9/uOrfqUY1kflRZtrUcMF0=" ];
};
```

On other systems, add the same two settings to `/etc/nix/nix.conf`.

The settings apply after a rebuild, so rebuild once with them before enabling Dux Files.

The cache has builds for the channel commits CI saw, so it applies when your `nixpkgs` input is on `nixos-unstable` or `nixos-26.05` and the flake follows it, as in the inputs above. A new channel commit reaches the cache within a few hours of the channel moving. Other nixpkgs commits, and overlays that change Qt or its dependencies, build from source.

Keep `inputs.nixpkgs.follows` on the flake input. A build against a different nixpkgs than your system mixes two versions of Qt and the graphics libraries in one session, which can crash.

## Rebuilding

```bash
# For home-manager standalone
home-manager switch

# For NixOS (with or without home-manager as a module)
sudo nixos-rebuild switch
```

## Troubleshooting

### Service doesn't start automatically

The service is off unless `systemd.enable = true`. Check it:

```bash
systemctl --user status dfiles
journalctl --user -u dfiles -f
```

### Portal dialogs still come from the old backend

xdg-desktop-portal reads its configuration once at startup. After enabling `portal.preferred`, restart it:

```bash
systemctl --user restart xdg-desktop-portal.service
```

`dfiles portal status` shows which backend is active.
