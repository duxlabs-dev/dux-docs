Dux Shell provides comprehensive IPC (Inter-Process Communication) functionality that allows external control of the shell through command-line commands. All IPC commands follow the format:

```bash
dms ipc call <target> <function> [parameters...]
```

## Discovering IPC commands

List all available targets and functions while DMS is running:

```bash
dms ipc list     # list all targets and functions
dms ipc          # same
dms ipc --help   # same, plus usage text
```

:::note
Live listing requires DMS to be running. If listing fails, use this page as the offline reference or start the shell with `dms run`.
:::

## Core Controls

### audio

Manage audio output and input devices.

| Function | Description | Parameters |
| --- | --- | --- |
| `setvolume <percentage>` | Set output volume | percentage (0-100) |
| `increment <step>` | Increase output volume | step (default: 5) |
| `decrement <step>` | Decrease output volume | step (default: 5) |
| `mute` | Toggle output mute | - |
| `setmic <percentage>` | Set microphone volume | percentage (0-100) |
| `micmute` | Toggle microphone mute | - |
| `cycleoutput` | Cycle through audio output devices | - |
| `setmono <bool>` | Enable or disable mono audio | true/false |
| `getmono` | Get current mono audio state | - |
| `status` | Get current audio status | - |

**Examples:**
```bash
dms ipc call audio setvolume 50
dms ipc call audio increment 10
dms ipc call audio mute
dms ipc call audio cycleoutput
dms ipc call audio setmono true
dms ipc call audio getmono
```

:::note
`audio setmic` and `audio micmute` remain available for backwards compatibility, but new scripts and keybinds should use the dedicated [`mic`](#mic) target below.
:::

### mic

Dedicated microphone input control with interactive OSD support.

| Function | Description | Parameters |
| --- | --- | --- |
| `setvolume <percentage>` | Set microphone volume | percentage (0-100) |
| `increment <step>` | Increase microphone volume (unmutes if muted) | step (default: 5) |
| `decrement <step>` | Decrease microphone volume (unmutes if muted) | step (default: 5) |
| `mute` | Toggle microphone mute | - |
| `status` | Get current microphone volume and mute state | - |

**Examples:**
```bash
dms ipc call mic setvolume 75
dms ipc call mic increment 5
dms ipc call mic decrement 10
dms ipc call mic mute
dms ipc call mic status
```

**Notes:**
- Adjusting the microphone volume triggers an interactive OSD (when `osdMicVolumeEnabled` is on) with a draggable slider and a mute toggle, mirroring the speaker volume OSD.
- `increment` and `decrement` automatically unmute the microphone before changing the level.

### brightness

Control display brightness for internal and external displays.

| Function | Description | Parameters |
| --- | --- | --- |
| `set <percentage> [device]` | Set brightness level | percentage (1-100), device (optional) |
| `increment <step> [device]` | Increase brightness | step, device (optional) |
| `decrement <step> [device]` | Decrease brightness | step, device (optional) |
| `status` | Get current brightness status | - |
| `list` | List all brightness devices | - |
| `enableExponential [device]` | Enable exponential brightness mode | device (optional, uses current if not specified) |
| `disableExponential [device]` | Disable exponential brightness mode | device (optional, uses current if not specified) |
| `toggleExponential [device]` | Toggle exponential brightness mode | device (optional, uses current if not specified) |

**Examples:**
```bash
dms ipc call brightness set 80
dms ipc call brightness increment 10 ""
dms ipc call brightness decrement 5 "intel_backlight"
dms ipc call brightness disableExponential "backlight:intel_backlight"
dms ipc call brightness toggleExponential
dms ipc call brightness set 40 "software:DP-2"
```

### night

Night mode (gamma/color temperature) control.

`gamma` and `contrast` are separate from night mode. They stay applied when night mode is off, and setting both back to 1.0 releases the gamma protocol so other tools can bind it again, unless an output is software-dimmed. Both need DMS API v34.

| Function | Description | Parameters |
| --- | --- | --- |
| `toggle` | Toggle night mode on/off | - |
| `enable` | Enable night mode | - |
| `disable` | Disable night mode | - |
| `status` | Get night mode status | - |
| `gamma [value]` | Get/set display gamma, applied with or without night mode | 0.5-2.0, 1.0 is neutral (optional) |
| `contrast [value]` | Get/set display contrast around mid-gray, applied with or without night mode | 0.5-2.0, 1.0 is neutral (optional) |
| `getCurrentTemp` | Get live gamma temperature | - |
| `getTargetTemp` | Get configured night temperature | - |
| `getDayTemp` | Get configured day temperature | - |
| `setTargetTemp <value>` | Set night temperature | value in Kelvin (2500-6000) |
| `setDayTemp <value>` | Set day temperature (applies when automation is on) | value in Kelvin (2500-6000) |
| `getSchedule` | Get automation details (mode, period, sun times, next transition) | - |
| `automation [mode]` | Get/set automation mode | "manual", "time", or "location" (optional) |
| `schedule <start> <end>` | Set time-based schedule | start time (HH:MM), end time (HH:MM) |
| `location <lat> <lon>` | Set location coordinates | latitude, longitude |

**Examples:**
```bash
dms ipc call night toggle
dms ipc call night gamma 1.2
dms ipc call night contrast 1.1
dms ipc call night getCurrentTemp
dms ipc call night setTargetTemp 4000
dms ipc call night setDayTemp 5500
dms ipc call night getSchedule
dms ipc call night automation time
dms ipc call night schedule 20:00 06:00
dms ipc call night location 40.7128 -74.0060
```

### lock

| Function | Description |
| --- | --- |
| `lock` | Lock the screen immediately |
| `lockAndOutputsOff` | Lock the screen, fade to black, then power off the monitors (GNOME Super+L style). Any input cancels the fade or wakes the monitors; the fade duration follows the fade-to-DPMS grace period setting. |

### sessions

Switch between logind sessions that are already running on the current seat. Wraps `loginctl list-sessions` and `loginctl activate`.

| Function | Description | Parameters |
| --- | --- | --- |
| `list` | List sessions as tab-separated rows (current marked `*current*`) | - |
| `refresh` | Re-enumerate sessions in the background | - |
| `open` | Refresh and open the Switch User picker | - |
| `activate <sessionId>` | Activate a session by its numeric logind ID | sessionId |
| `switchTo <target>` | Activate a session by username or session ID | target (username or sessionId) |

**Examples:**
```bash
# See what's switchable
dms ipc call sessions list

# Open the Switch User picker (good for a keybind)
dms ipc call sessions open

# Jump straight to another logged-in user
dms ipc call sessions switchTo testuser2

# Or by session ID
dms ipc call sessions activate 4
```

:::note
This only switches between sessions that *already exist* on the current seat. Creating a brand-new session for a user who isn't logged in needs a multi-session greeter (greetd-flexiserver / GDM / LightDM); the picker's empty state offers a Log out fallback to reach the greeter.
:::

The `dms switch-user [target]` CLI command wraps the same calls with a friendlier interactive list when no target matches.

### inhibit

Idle inhibitor control to prevent automatic sleep/lock.

| Function | Description |
| --- | --- |
| `toggle` | Toggle idle inhibit state |
| `enable` | Enable idle inhibit indefinitely (prevent sleep) |
| `enableFor <minutes>` | Enable idle inhibit for a number of minutes |
| `disable` | Disable idle inhibit (allow sleep) |
| `status` | Report whether idle inhibit is on, and the remaining time when a timer is set |
| `reason <text>` | Set the inhibit reason; pass an empty string to read the current one |

**Examples:**
```bash
dms ipc call inhibit toggle
dms ipc call inhibit enable
dms ipc call inhibit enableFor 60
dms ipc call inhibit status
dms ipc call inhibit reason "rendering a video"
dms ipc call inhibit reason ""   # prints the current reason
```

The state is saved in the session, like Do Not Disturb, so it survives a shell
restart — whether that comes from `dms restart` or from systemd bringing the
service back.

### powerprofile

Power profile control via the PowerProfiles D-Bus interface. Changes stay in sync with DMS UI and trigger the power profile OSD when enabled in Settings → OSD.

Requires either `power-profiles-daemon`, `tuned` with `tuned-ppd` or `tlp` with `tlp-pd`, to be installed and running. Works on all compositors.

| Function | Description | Parameters |
| --- | --- | --- |
| `open` | Show the power profile picker modal | - |
| `close` | Close the power profile picker modal | - |
| `toggle` | Toggle power profile picker modal visibility | - |
| `list` | List available profile slugs (one per line) | - |
| `status` | Get the currently active profile slug | - |
| `set <profile>` | Set the active power profile | slug or alias (see below) |
| `cycle` | Cycle to the next available profile | - |

**Profile slugs and aliases for `set`:**
- `power-saver` — also `powersaver`, `saver`, `0`
- `balanced` — also `1`
- `performance` — also `2` (only when supported by hardware)

**Cycle order:** `power-saver` → `balanced` → `performance` → `power-saver` (skips profiles not available on your hardware).

**Examples:**
```bash
dms ipc call powerprofile status
dms ipc call powerprofile list
dms ipc call powerprofile cycle
dms ipc call powerprofile set balanced
dms ipc call powerprofile set performance
dms ipc call powerprofile toggle
```

**Notes:**
- `list` returns only profiles available on your system (performance is omitted when unsupported)
- `status` returns the current slug: `power-saver`, `balanced`, or `performance`
- Returns `ERROR: power-profiles-daemon not available` when no PowerProfiles daemon (`power-profiles-daemon`, `tuned-ppd` or `tlp-pd`) is running
- Returns `ERROR: Failed to set power profile` if the profile change could not be applied

### wellbeing

Digital Wellbeing screen time tracking and limits. Usage is recorded by the DMS server, so tracking needs a running `dms` backend with wellbeing support.

| Function | Description | Parameters |
| --- | --- | --- |
| `toggle` | Toggle screen time tracking | - |
| `enable` | Enable screen time tracking | - |
| `disable` | Disable screen time tracking | - |
| `status` | Report tracking state, today's screen time and the daily limit | - |
| `today` | Today's screen time in seconds (`0` while tracking is off) | - |
| `dailyLimit <minutes>` | Set the daily screen time limit; `0` clears it, empty string prints the current one | minutes |
| `appLimit <appId> <minutes>` | Set a daily limit for one app; `0` clears it, empty string prints the current one | app id, minutes |

To open the Digital Wellbeing dashboard tab, use `dms ipc call dash open wellbeing`. The tab only appears while tracking is enabled.

**Examples:**
```bash
dms ipc call wellbeing status
dms ipc call wellbeing toggle
dms ipc call wellbeing today
dms ipc call wellbeing dailyLimit 180
dms ipc call wellbeing dailyLimit ""   # prints the current limit
dms ipc call wellbeing appLimit firefox 60
dms ipc call wellbeing appLimit firefox 0
```

**Keybind examples:**
```kdl
// niri
Mod+Shift+W { spawn "dms" "ipc" "call" "dash" "toggle" "wellbeing"; }
```
```lua
-- Hyprland
hl.bind(mod .. " + SHIFT + W", hl.dsp.exec_cmd("dms ipc call dash toggle wellbeing"))
```

Both actions are also available in **Settings → Keyboard shortcuts** as *Dashboard: Digital Wellbeing* and *Screen Time Tracking: Toggle*.

## Wallpaper & Profile

### wallpaper

Wallpaper management with support for global and per-monitor configurations.

#### Global Wallpaper Functions

| Function | Description | Parameters |
| --- | --- | --- |
| `get` | Get current wallpaper path | - |
| `set <path>` | Set wallpaper | path to image file |
| `clear` | Clear all wallpapers | - |
| `next` | Cycle to next wallpaper | - |
| `prev` | Cycle to previous wallpaper | - |

#### Per-Monitor Functions

| Function | Description | Parameters |
| --- | --- | --- |
| `getFor <screen>` | Get wallpaper for monitor | monitor name (e.g., "DP-2") |
| `setFor <screen> <path>` | Set wallpaper for monitor | monitor name, path to image |
| `nextFor <screen>` | Cycle to next wallpaper | monitor name |
| `prevFor <screen>` | Cycle to previous wallpaper | monitor name |

**Examples:**
```bash
# Global wallpaper mode
dms ipc call wallpaper set /path/to/image.jpg
dms ipc call wallpaper next

# Per-monitor wallpaper mode
dms ipc call wallpaper setFor DP-2 /path/to/image1.jpg
dms ipc call wallpaper setFor eDP-1 /path/to/image2.jpg
dms ipc call wallpaper nextFor eDP-1

# Clear and return to global mode
dms ipc call wallpaper clear
```

**Note:** When per-monitor mode is enabled, legacy global functions will return error messages directing you to use the per-monitor equivalents.

## Appearance Controls

### theme

Theme mode control (light/dark mode switching).

| Function | Description |
| --- | --- |
| `toggle` | Toggle between light and dark themes |
| `light` | Switch to light theme |
| `dark` | Switch to dark theme |
| `getMode` | Get current theme mode |

**Examples:**
```bash
dms ipc call theme toggle
dms ipc call theme dark
```

### bar

Control individual bars using flexible selectors.

| Function | Description | Parameters |
| --- | --- | --- |
| `reveal <selector> <value>` | Show a bar | selector + value |
| `hide <selector> <value>` | Hide a bar | selector + value |
| `toggle <selector> <value>` | Toggle bar visibility | selector + value |
| `status <selector> <value>` | Get bar visibility status | selector + value |
| `autoHide <selector> <value>` | Enable auto-hide mode | selector + value |
| `manualHide <selector> <value>` | Disable auto-hide mode | selector + value |
| `toggleAutoHide <selector> <value>` | Toggle auto-hide mode | selector + value |
| `toggleReveal <selector> <value>` | Toggle the runtime reveal/tuck state for an auto-hidden bar | selector + value |
| `getPosition <selector> <value>` | Get bar position | selector + value |
| `setPosition <selector> <value> <position>` | Set bar position | selector + value + position (top, bottom, left, right) |

**Note:** `toggleReveal` only affects bars with auto-hide enabled. Moving the pointer into the bar reveal area clears the IPC reveal state and hands control back to normal hover auto-hide behavior.

**Selectors:**
- `index` - Select by position (0-based)
- `id` - Select by unique bar ID
- `name` - Select by bar name

**Examples:**
```bash
# By index
dms ipc call bar hide index 0
dms ipc call bar reveal index 1
dms ipc call bar toggle index 0

# By name
dms ipc call bar toggle name "Main Bar"
dms ipc call bar status name "Secondary"

# By ID
dms ipc call bar reveal id abc123

# Auto-hide controls
dms ipc call bar autoHide index 0
dms ipc call bar manualHide name "Main Bar"
dms ipc call bar toggleAutoHide index 1
dms ipc call bar toggleReveal index 0

# Position controls
dms ipc call bar getPosition index 0
dms ipc call bar getPosition id default
dms ipc call bar setPosition index 0 top
dms ipc call bar setPosition id default left
```

**Dank Island and Dot:** A bar instance may use the Island or Dot layout (Settings → Bar → Layout). Both are still listed by `bar` selectors (`index` includes them), but visibility and auto-hide commands return `BAR_IS_ISLAND` — use the [`island`](#island) or [`dot`](#dot) target instead. `setPosition` accepts only `top` and `bottom` for an edge island; for a free island it only picks the orientation (`top`/`bottom` horizontal, `left`/`right` vertical).

### island

Dank Island activity surface. Requires a bar instance using the Island layout and enabled. Commands target the focused screen unless you use an `*On` variant. This target never answers for a [Dot](#dot); use `openInstance` / `toggleInstance` with a bar id to address either kind explicitly.

| Function | Description | Parameters |
| --- | --- | --- |
| `open <activity>` | Expand into the requested activity | activity id |
| `toggle <activity>` | Collapse if expanded; otherwise expand into the activity | activity id |
| `show <activity>` | Switch the compact face without expanding | activity id |
| `close` | Collapse back to the compact face | - |
| `cycle` | Cycle activities (`home` → `media` when available → `launcher` when Default Opens is Island → `controlcenter` → `wallpaper` → `weather` when enabled → `notificationcenter`) | - |
| `status` | JSON snapshot of the island on the focused screen | - |
| `notifications` | Toggle the notification center as an island activity | - |
| `openOn` / `toggleOn` / `showOn` / `closeOn` / `cycleOn` / `statusOn` / `notificationsOn` | Same actions on a named monitor | activity (where required) + screen name |
| `openInstance` / `toggleInstance` | Address one island or dot instance by bar id | activity + screen name + bar id |
| `move <x> <y>` | Move a free island's centre to a pixel position on its screen, clamped fully on screen | x, y |
| `moveOn <screen> <x> <y>` | Same on a named monitor | screen name, x, y |
| `center` / `centerOn <screen>` | Recentre a free island, useful to recover one parked off a disconnected display | screen name (for `centerOn`) |

**Activities:** `home` (clock), `media`, `launcher`, `controlcenter` (`control-center`, `cc`), `wallpaper`, `weather`, `notificationcenter` (`notifications`, `notification-center`, `nc`), `clipboard`, `powermenu` (`power-menu`). Unrecognized ids open `home`. `media` needs an active session; `weather` needs weather enabled. A screen name with no island returns `DANK_ISLAND_UNAVAILABLE` rather than falling back to another display.

**Free placement:** With Float on, Settings → Bar → General → Placement offers **Edge** (floats along its edge) or **Anywhere** (a draggable island you can park at any point on the display). `move` / `center` only apply to an Anywhere island and return `DANK_ISLAND_NOT_FREE` otherwise. `status` reports `free` plus the anchor `x` / `y` for free islands.

When Dank Island or a Dot is the sole top chrome on the focused display, or an island or dot there has **Shared shortcuts** set to **Always here** or is the last one clicked under **Last used on this screen**, these existing targets open island activities instead of their popouts:

- `control-center` `open` / `toggle` / `hide` / `status`
- `notifications` `open` / `toggle` / `close` (the notification modal is used if the island does not own the screen)
- `dash` `open` / `toggle` with `overview` (or no tab), `media`, `wallpaper`, or `weather`, and `dash close` while those activities are open
- `clipboard` `open` / `toggle` / `close`
- `powermenu` `open` / `toggle` / `close`

`spotlight` and `launcher` open the island launcher when **Launcher → Default Opens** is Island, and fall back to Spotlight if the focused screen has no island. An island or dot that owns shared shortcuts also uses the island launcher, regardless of the default launcher style; see [shared shortcut routing](#dot).

**Examples:**
```bash
dms ipc call island toggle home
dms ipc call island open media
dms ipc call island open launcher
dms ipc call island open controlcenter
dms ipc call island open wallpaper
dms ipc call island open weather
dms ipc call island open notifications
dms ipc call island open powermenu
dms ipc call island show home
dms ipc call island toggleOn media DP-1
dms ipc call island cycle
dms ipc call island close
dms ipc call island status
dms ipc call island move 1600 900
dms ipc call island centerOn DP-1
dms ipc call island openInstance controlcenter DP-1 default
```

### dot

Dank Dot: a bar instance using the Dot layout (Settings → Bar → Layout → Dot). It rests as a small draggable dot anywhere on the display, floats over every other bar, and opens the same activities as the island. Fades and shrinks when idle; hover or drag to wake it. Commands target the focused screen unless you use an `*On` variant, and answer only for dots — an [`island`](#island) never responds here.

| Function | Description | Parameters |
| --- | --- | --- |
| `open <activity>` | Expand the dot into the requested activity | activity id |
| `toggle <activity>` | Collapse if expanded; otherwise expand into the activity | activity id |
| `show <activity>` | Switch the pending activity without expanding | activity id |
| `close` | Collapse back to the dot | - |
| `cycle` | Cycle activities, same order as the island | - |
| `status` | JSON snapshot of the dot (`screen`, `x`, `y`, `idle`, `activity`, `expanded`, …) | - |
| `notifications` | Toggle the notification center as a dot activity | - |
| `move <x> <y>` | Move the dot's centre to a pixel position on its screen, clamped fully on screen | x, y |
| `center` | Recentre the dot on its screen | - |
| `openOn` / `toggleOn` / `showOn` | Same activity action on a named monitor | activity + screen name |
| `closeOn` / `cycleOn` / `statusOn` / `notificationsOn` / `centerOn` | Same action on a named monitor | screen name |
| `moveOn` | Move the dot on a named monitor | screen name + x + y |
| `openInstance` / `toggleInstance` | Address one dot instance by bar id | activity + screen name + bar id |

Activities and their aliases match the [`island`](#island) target. Replies use a `DANK_DOT_` prefix (`DANK_DOT_OPEN`, `DANK_DOT_CLOSED`, `DANK_DOT_MOVED`, `DANK_DOT_UNAVAILABLE`, …).

With bars on the same screen, the dot only reacts to clicks and this target by default; the shared `control-center`, `notifications`, `dash`, `spotlight` and `launcher` targets keep opening your bar popouts. On a screen with no bar and no island, the dot is the sole chrome and takes them automatically.

**Shared shortcuts** (Settings → Bar → General, with the dot or an island selected) changes this per instance:

- **Normal routing** — the default above.
- **Always here** — shared targets open in this dot or island, even when bars share the screen. Only one instance per screen can hold this; choosing it on another resets the previous one to Normal.
- **Last used on this screen** — shared shortcuts follow the last bar, island or dot you clicked. Each screen remembers its own destination until the shell restarts; clicking a standard bar restores its popouts and launcher. Before the first click, Normal routing applies.

All three work with the Frame layout and do not require changing your launcher style. Explicit `dot` and `island` commands keep their own targets regardless.

**Examples:**
```bash
dms ipc call dot toggle home
dms ipc call dot open launcher
dms ipc call dot open controlcenter
dms ipc call dot notifications
dms ipc call dot move 1600 900
dms ipc call dot moveOn DP-1 200 200
dms ipc call dot center
dms ipc call dot close
dms ipc call dot status
```

### dock

Dock visibility and behavior control.

A dock is one of possibly several configurations, each holding one screen edge. Functions without a selector act on the dock of the focused screen; the `*For` variants take a selector naming a dock by its id or its display name (as shown in **Settings → Dock → Configuration**). Any function returns `DOCK_NOT_FOUND` when no dock matches.

| Function | Description |
| --- | --- |
| `reveal` / `revealFor <selector>` | Enable the dock |
| `hide` / `hideFor <selector>` | Disable the dock |
| `toggle` / `toggleFor <selector>` | Toggle the dock |
| `status` / `statusFor <selector>` | Get dock visibility status |
| `edit` / `editFor <selector>` | Open the dock's widget edit mode, or `DOCK_HIDDEN` when the dock is disabled |
| `autoHide` | Enable auto-hide mode |
| `manualHide` | Disable auto-hide mode |
| `toggleAutoHide` | Toggle auto-hide mode |
| `autoHideFor <selector> <enabled>` | Set auto-hide on a named dock, `true` or `false` |

**Examples:**
```bash
dms ipc call dock toggle
dms ipc call dock hide
dms ipc call dock reveal
dms ipc call dock status
dms ipc call dock edit

# A specific dock, by display name or id
dms ipc call dock revealFor Dock
dms ipc call dock hideFor dock_1757371200000
dms ipc call dock editFor Dock

# Auto-hide controls
dms ipc call dock autoHide
dms ipc call dock manualHide
dms ipc call dock toggleAutoHide
dms ipc call dock autoHideFor Dock true
```

### widget

Control bar widget popouts, menus, and visibility (including plugins).

| Function | Description | Parameters |

| `hide <widgetId>` | Force widget to be hidden | widget ID |
| `reset <widgetId>` | Clear visibility override, return to normal behavior | widget ID |

**Examples:**
```bash

dms ipc call widget openWith launcherButton all
dms ipc call widget openWith launcherButton files
dms ipc call widget openWith launcherButton apps
dms ipc call widget openWith launcherButton plugins
dms ipc call widget toggleWith launcherButton files

# Open widget popout with a pre-filled search query

dms ipc call widget toggleQuery launcherButton "settings"

# Control widget visibility on the bar

dms ipc call widget hide weather
dms ipc call widget reveal weather
dms ipc call widget reset weather
```

**Notes:**
- Use `list` to discover available widget IDs with their current visibility state (`[visible]` or `[hidden]`)
- Widget IDs come from the widgets in your bar settings; a disabled widget still opens its popout
- With several bars, popouts open on the focused screen, preferring a bar where the widget is shown, then the bar you last clicked when **Last used on this screen** is on. A widget on a hidden bar opens anchored where that bar sits
- The `status` function returns "visible" or "hidden" for the widget **popout** state
- The `visibility`, `reveal`, `hide`, and `reset` functions control the widget's **bar presence** (whether it appears on the bar at all)
- Plugins can define conditional visibility via `visibilityCommand` — use `reset` to return to that behavior after overriding

### niri

**Screenshot functions require niri 25.11+.** Automatic touchpad OSD updates require a niri build with `TouchpadToggled` IPC events (currently niri-git).

Screenshot and touchpad controls for the niri compositor. Captures are opened in your configured editor for markup and annotation.

| Function | Description |
| --- | --- |
| `screenshot` | Interactive selection screenshot |
| `screenshotScreen` | Capture entire screen |
| `screenshotWindow` | Capture focused window |
| `showTouchpadOsd <enabled>` | Show the hardware-reported touchpad state (`true` for on, `false` for off), without changing it |

**Examples:**
```bash
dms ipc call niri screenshot
dms ipc call niri screenshotScreen
dms ipc call niri screenshotWindow
dms ipc call niri showTouchpadOsd true
dms ipc call niri showTouchpadOsd false
```

**Touchpad toggle:** DMS listens for niri's `TouchpadToggled` events and shows the reported software-toggle state. Native keybindings and `niri msg action toggle-touchpad` both trigger the OSD. This state describes niri's software toggle; hardware switches and `input { touchpad { off; } }` can still disable the device.

The following binding calls niri directly. It uses `spawn` so the config remains parseable on older niri versions; toggling still requires the `toggle-touchpad` action, and the OSD requires the new events:

```kdl
XF86TouchpadToggle allow-when-locked=true repeat=false {
    spawn "niri" "msg" "action" "toggle-touchpad";
}
```

**Hardware On/Off keys:** For laptops that enable or disable the touchpad in hardware and emit `XF86TouchpadOn` or `XF86TouchpadOff`, these bindings show the corresponding OSD without sending a toggle action. They do not require niri's `toggle-touchpad` action or `TouchpadToggled` events.

```kdl
XF86TouchpadOn allow-when-locked=true repeat=false {
    spawn "dms" "ipc" "call" "niri" "showTouchpadOsd" "true";
}
XF86TouchpadOff allow-when-locked=true repeat=false {
    spawn "dms" "ipc" "call" "niri" "showTouchpadOsd" "false";
}
```

The OSD can be turned off in Settings → OSD → Touchpad.

**Configuration:**

Set the `DMS_SCREENSHOT_EDITOR` environment variable to choose your preferred screenshot editor backend:

```bash
# Use Swappy (default)
export DMS_SCREENSHOT_EDITOR=swappy

# Use Satty
export DMS_SCREENSHOT_EDITOR=satty
```

**Requirements:** niri compositor and your chosen screenshot editor (Swappy or Satty) must be installed.

#### Cycling connected displays

`cycle` walks connected outputs in name order and leaves a single display enabled. If the next output is disabled, DMS enables it and waits for confirmation before disabling the others. If it is already enabled, the others are disabled immediately.

The command returns as soon as the switch is started:

| Status | Meaning |
| --- | --- |
| `OUTPUT_CYCLE_ACCEPTED` | Switching started, not a confirmation that it finished |
| `OUTPUT_CYCLE_BUSY` | Still waiting for the previously selected output to become enabled |
| `OUTPUT_CYCLE_NOOP` | Fewer than two outputs connected, or switching could not start |
| `OUTPUT_CYCLE_UNSUPPORTED` | Compositor is not niri, its IPC socket is unavailable, or output-state notifications are unavailable |

If the selected display disconnects and no connected display is left enabled, DMS enables the previous connected display in the cycle. The cycle order lives in memory and resets when DMS restarts.

:::note
`cycle` is niri only, unlike the profile functions above.
:::

## Scripting and Automation

IPC commands are designed for integration with keybindings, scripts, and automation tools.

### Time-based Automation

```bash
#!/bin/bash
# Toggle night mode based on time of day
hour=$(date +%H)
if [ $hour -ge 20 ] || [ $hour -le 6 ]; then
    dms ipc call night enable
else
    dms ipc call night disable
fi
```

### Status Checking

```bash
# Check if screen is locked before performing action
if dms ipc call lock isLocked | grep -q "false"; then
    dms ipc call notifications open
fi
```

### Conditional Logic

```bash
# Increase brightness only if below threshold
current=$(dms ipc call brightness status | grep -oP '\d+')
if [ "$current" -lt 50 ]; then
    dms ipc call brightness set 50
fi

# Cycle power profile only when not in performance mode
if [ "$(dms ipc call powerprofile status)" != "performance" ]; then
    dms ipc call powerprofile cycle
fi
```

## Return Values

Most IPC functions return string messages indicating:
- Success confirmation with current values
- Error messages if operation fails
- Status information for query functions
- Empty/void return for simple action functions

Functions that return void (like media controls) execute the action but don't provide feedback. Check the application state through other means if needed.
