Dux Greeter can be installed on NixOS using the NixOS module. This guide covers the flake-based installation method.

:::info[Native NixOS module Available]
Dux Greeter is available in nixpkgs stable (26.05). If you're on NixOS 26.05+, the [Installation - NixOS](./nixos.mdx) method is recommended and doesn't require flakes.
Use the Flake option if you want quicker updates.

:::

## Installation

### 1. Add Flake Inputs

Add the required flake inputs to your `flake.nix` if you haven't yet:

```nix title="flake.nix"
{
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";

    dux-greeter = {
      url = "github:duxlabs-dev/dux-greeter";
      inputs.nixpkgs.follows = "nixpkgs";
    };
  };
}
```

### 2. Import the NixOS Module

Add the Dux Greeter module to your NixOS configuration imports:

```nix
imports = [
  inputs.dux-greeter.nixosModules.default
];
```

:::note[NixOS module only]

Dux Greeter is only available as a NixOS module (not as a home-manager module), since it needs to run at the system level for login management.

:::

### 3. Enable Dux Greeter

Enable and configure the greeter in your NixOS configuration:

```nix
programs.dms-greeter = {
  enable = true;
  compositor.name = "niri";  # Or "hyprland" or "sway"
};
```

:::info[Configure in NixOS, not home-manager]

Unlike Dux Modular Shell which can be installed via either the NixOS module or home-manager module, Dux Greeter must be configured in your NixOS system configuration (not in home-manager).

:::

:::note[Compositors come from NixOS config]

Compositors must be installed via NixOS configuration to appear in Dux Greeter, not via home-manager.

:::

## Configuration Options

```nix
programs.dms-greeter = {
  compositor = {
    name = "niri"; # Required. Can be also "hyprland" or "sway"
    customConfig = ''
      # Optional custom compositor configuration
    '';
  };

  # Sync your user's Dux Modular Shell theme with the greeter. You'll probably want this
  configHome = "/home/yourusername";

  # Custom config files for non-standard config locations
  configFiles = [
    "/home/yourusername/.config/dms/settings.json"
  ];

  # Save the logs to a file
  logs = {
    save = true;
    path = "/tmp/dms-greeter.log";
  };

  # Custom dux-qt-base runtime library, built into dms-greeter (optional,
  # needs a dux-qt-base flake input that follows your nixpkgs; defaults to
  # the one dux-greeter pins, built against your nixpkgs)
  duxQtBase.package = inputs.dux-qt-base.packages.${pkgs.stdenv.hostPlatform.system}.dux-qt-base;
};
```

The greeter no longer uses a Quickshell package. The old `quickshell.package` option is removed; evaluation fails with a message pointing to `duxQtBase.package`.

## Binary Cache

dux-qt-base, the Quickshell runtime built into Dux Greeter, takes a while to build from source. CI publishes `x86_64-linux` and `aarch64-linux` builds of every commit on `master` to `nix-cache.duxlabs.dev`, built against the latest `nixos-unstable` and `nixos-26.05` channel commits. Releases up to 2.1 use Quickshell from nixpkgs and don't need the cache.

Add the cache to your NixOS configuration:

```nix
nix.settings = {
  extra-substituters = [ "https://nix-cache.duxlabs.dev" ];
  extra-trusted-public-keys = [ "dux-1:lrBykuzHKu9F6WsCbK83C9/uOrfqUY1kflRZtrUcMF0=" ];
};
```

The settings apply after a rebuild, so rebuild once with them before enabling Dux Greeter.

The cache has builds for the channel commits CI saw, so it applies when your `nixpkgs` input is on `nixos-unstable` or `nixos-26.05` and the flake follows it, as in the inputs above. A new channel commit reaches the cache within a few hours of the channel moving. Other nixpkgs commits, and overlays that change Qt or its dependencies, build from source.

Keep `inputs.nixpkgs.follows` on the flake input. A build against a different nixpkgs than your system mixes two versions of Qt and the graphics libraries in one session, which can crash.

## Rebuilding

After making configuration changes, don't forget to rebuild your configuration:

```bash
sudo nixos-rebuild switch
```
