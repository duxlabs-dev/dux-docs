## niri

niri is the compositor we drive every day, so DMS 2.1 already supports everything coming in niri's next stable release. DMS asks the installed niri once with `niri validate` and only shows the newer options when your niri accepts them, so niri 26.04 keeps working as it does today.

- **Keyboard shortcuts:** **Release** and **Non-consuming** bind options, and binds on a lone modifier. On the next release, tapping `Mod` on its own toggles the overview and `Mod+Shift+?` opens the cheatsheet.
- **Window rules:** **VRR Fullscreen Only**, **On activation** (Focus, Ignore, or Mark urgent), and **Pinch sensitivity**.
- **Input and displays:** touchpad pinch sensitivity and **Max bits per channel** for each output.
- **Conflict detection** understands modifier order and left and right modifiers, so it catches the same clashes niri does.
- **Bar:** overlay bars animate out when a window goes fullscreen ([steven12138](https://github.com/steven12138)).

The binds that depend on your niri version live in `dms/binds-next.kdl`, which DMS keeps up to date, and `dms doctor` warns if your `config.kdl` doesn't include it. See [Next niri release](/docs/dms/compositors#next-niri-release).

## Hyprland

2.1 is Lua only. Hyprland 0.57 reads nothing but `hyprland.lua`, so DMS has dropped legacy `hyprland.conf` support entirely and reads and writes Lua on every Hyprland it supports, from 0.55 up. See [Upgrade Notes](#hyprland-lua-config-only) to switch over.

- **Hyprland 0.57:** the remaining gaps are closed. Screenshots are no longer rotated twice, and `dms doctor` warns when Quickshell is too old for 0.57's named and special workspaces, when your config uses deprecated options, and when the greeter isn't on Lua yet.
- **Wobbly windows:** damping, mass, and mesh sit next to intensity and stiffness in **Settings → System & integrations → Hyprland** ([alamin147](https://github.com/alamin147)).
- **Monitor profiles** are written with `desc:` identifiers, so they follow a display across ports.
- **Keybinds:** `dms setup` refreshes `binds.lua` even when you keep your main config, Lua function binds land in the right cheatsheet category, and DMS warns when an action is missing its arguments.
- **Dock:** hides for floating windows you move or resize with keybinds.

See [Hyprland](/docs/dms/compositors#hyprland-configuration).

## mangowm

DMS now works natively with both mangowm config formats. Keep `config.conf` or move to `config.toml`: DMS finds and repairs its includes in either, without creating a `config.conf` that would shadow your TOML file, and the cheatsheet, window rules, and monitor rules read TOML directly. Bind conflicts are checked per key mode, and `bindc` is honored.

DMS also targets mangowm 0.18 and newer only. The pre-0.18 key names and DMS's own translation layer for them are gone, along with `dms config mango-migrate`. See [Upgrade Notes](#mangowm-018-or-newer).

- Workspace apps stay on their own monitor ([tomups](https://github.com/tomups)).
- mangowm no longer runs its layer animations on DMS surfaces, so the shell's own animations play clean.

See [mangowm](/docs/dms/compositors#mangowc-configuration).

## Dux installer on Fedora Atomic

`duxinstall` now supports immutable Fedora: Silverblue, Kinoite, Sericea, Onyx, Bazzite, Bluefin, Aurora, Zirconium, and other rpm-ostree or bootc images based on Fedora.

```bash
curl -fsSL https://install.duxlabs.dev | sh
```

On an image it never runs a package command or asks for a password. It checks what the image already has, prints the `rpm-ostree install` commands for anything missing, and stops. Layer the packages, reboot, and run it again: it picks up your earlier choices and deploys the configuration into your home directory. Switching between stable and git builds prints the matching `rpm-ostree` swap the same way, and headless mode (`-c`, `-t`, `-y`) works on images too. The greeter isn't set up for you on an image; the installer prints the `dms-greeter install --yes` command to run afterwards.

The installer can also set up [Dux Files](/docs/dfiles) now. See [Fedora Atomic & bootc images](/docs/duxinstall#fedora-atomic--bootc-images).

## Upgrade Notes

### Move to the Dux Labs repositories

Everyone on a packaged install needs this one. As 2.0 promised, the AvengeMedia and DankLinux package repositories are being retired. A full set of Dux Labs repositories has been built out in parallel with them, covering Arch and the AUR, COPR, Open Build Service, Void, and Ubuntu's Launchpad PPAs, and from 2.1 installs and updates come from Dux Labs.

:::tip[Run this once after updating]

```bash
dms migrate dux
```

It lists every repository it will move and asks before it changes anything. Add `--dry-run` to only print the commands. It's safe to run again: repositories that already moved are skipped.

:::

| Distribution | What `dms migrate dux` moves |
|---|---|
| Fedora, Enterprise Linux 10 (COPR) | `avengemedia/*` to `duxlabs/dms`, `duxlabs/dms-git`, and `duxlabs/dux-repo` |
| Ubuntu (Launchpad PPA) | `ppa:avengemedia/*` to `ppa:duxlabs/dms`, `ppa:duxlabs/dms-git`, and `ppa:duxlabs/dux-repo` |
| Debian, openSUSE (Open Build Service) | `home:AvengeMedia:*` to `home:duxlabs-dev:dms`, `home:duxlabs-dev:dms-git`, and `home:duxlabs-dev:dux-repo`, switching renamed packages over on the way |
| Void (XBPS) | `void.danklinux.com` to `void.duxlabs.dev` |
| Fedora Atomic (Silverblue, Kinoite, Bazzite) | Prints the `.repo` swap for you to run |

**Arch and the AUR** aren't covered by `dms migrate dux`: there's no repository to switch, because the packages themselves carry the Dux names (`dux-shell` in extra, `dux-shell-git` and `dux-greeter-bin` in the AUR). TODO: the exact Arch/AUR switch-over steps.

Only repositories you have enabled are touched. Afterwards, [`dms doctor`](/docs/dms/cli-doctor#package-repos) shows whether any legacy repositories are left. The full list of commands for each distribution is in [Migrate repositories](/docs/dms/cli-migrate).

The [Dux installer](/docs/duxinstall) now installs from the Dux Labs repositories too.

### Hyprland: Lua config only

DMS no longer reads or manages `hyprland.conf` and needs Hyprland 0.55 or newer. Nothing is converted for you: `dms setup` writes a fresh `hyprland.lua` and the `dms/*.lua` fragments, backing up any existing `hyprland.lua` first, and leaves your old `hyprland.conf` in place, unused. Re-add your shortcuts, window rules, and displays from Settings or `dms/binds-user.lua`. See [Coming from hyprland.conf](/docs/dms/compositors#coming-from-hyprlandconf).

### mangowm 0.18 or newer

mangowm 0.18 renamed its config keys to snake_case (`exec-once` is now `exec_once`, `windowrule` is `window_rule`, and so on), and DMS now writes only the new names. `dms config mango-migrate` is gone: run the `migrate-config-keys.sh` from [mangowm's 0.18.0 release](https://github.com/DreamMaoMao/mangowc/releases/tag/0.18.0) over `~/.config/mango` instead. If you ran that script from a timer or cron job to keep up with DMS, remove it. `dms doctor` lists any keys mangowm still rejects.
