Dux Shell works with any Wayland compositor, but we provide optimized configurations for niri, Hyprland, Sway, MangoWC, labwc, and Miracle WM. These configs include DMS-specific keybindings, proper layer shell rules, and recommended settings.

## niri Configuration

niri uses the KDL configuration format. Dux Shell integrates seamlessly with niri's scrollable tiling layout.


### Key Configuration Sections

DMS will automatically apply key binds, gaps, window radius, and colors if you include the following files in your niri config. You can customize gaps, border radius, and window radius in **Settings → Compositor**.


```kdl
// Add to the end of ~/.config/niri/config.kdl
include "dms/colors.kdl"
include "dms/layout.kdl"
include "dms/alttab.kdl"
include "dms/binds.kdl"
```

:::tip
Be sure that all files exist before including them in the niri configuration.
```bash
mkdir -p ~/.config/niri/dms
touch ~/.config/niri/dms/{colors,layout,alttab,binds}.kdl
```
:::

For manual configuration recommendations, continue below.

#### Layout

The niri layout should have a transparent background, in order to integrate wallpapers onto the overview.

```kdl
layout {
    // You can tailor the gaps to fit dms spacing.
    gaps 5
    background-color "transparent"
}
```

#### Layer Rules

Tell niri to place the wallpaper on the overview.

```kdl
layer-rule {
    match namespace="^quickshell$"
    place-within-backdrop true
}
```

If "Blur Layer" is enabled, you can place the blurred wallpaper on the overview.

```kdl
layer-rule {
    match namespace="dms:blurwallpaper"
    place-within-backdrop true
}
```
For more about layer rules see [layer rules](./layers.mdx).

For systemd autostart setup, see the [Installation guide](./installation#niri). If you prefer not to use systemd, add DMS directly to your niri config:

```kdl
spawn-at-startup "dms" "run"
```

### Window Rules

Recommended window rules, tailor to your preferences:

```kdl
window-rule {
    match app-id=r#"^org\.gnome\."#
    draw-border-with-background false
    geometry-corner-radius 12
    clip-to-geometry true
}

window-rule {
    match app-id=r#"^org\.wezfurlong\.wezterm$"#
    match app-id="Alacritty"
    match app-id="zen"
    match app-id="com.mitchellh.ghostty"
    match app-id="kitty"
    draw-border-with-background false
}

window-rule {
    match is-active=false
    opacity 0.9
}

window-rule {
    geometry-corner-radius 12
    clip-to-geometry true
}

// Open DMS windows as floating by default (optional - DMS can manage this for you, see tip below)
window-rule {
    match app-id=r#"^dev\.duxlabs\.shell$"#
    open-floating true
}
```

:::tip[DMS-managed floating rule]
DMS can manage this rule itself via **Settings → Theme & Colors → Floating Windows → Open Windows Floating** (on by default). The rule lives in a managed fragment at `~/.config/niri/dms/windowrules.kdl`; if that fragment isn't included in your config yet, a **First Time Setup** banner on the same page creates it and adds the include when you click **Setup**. DMS floating windows use app ID `dev.duxlabs.shell` — remove any hand-written rules targeting the old `org.quickshell` ID.
:::

## Hyprland Configuration

Hyprland uses a Lua config at `~/.config/hypr/hyprland.lua`. DMS needs **Hyprland 0.55 or newer**, the first release that loads it; `dms setup` refuses to write the Lua config on older versions.

Hyprland 0.57 reads only `hyprland.lua`; the `hyprland.conf` format is gone. DMS reads and writes Lua on every supported version, so on 0.55 and 0.56 the keybind, window rule and display pages in Settings stay read-only until `hyprland.lua` exists. See [Coming from hyprland.conf](#coming-from-hyprlandconf).

### Config layout

Hyprland must be started with the Lua config for any of this to apply:

```sh
Hyprland -c ~/.config/hypr/hyprland.lua
```

If Hyprland warns that it is using an autogenerated config, the session is not on the DMS config yet; run `dms setup`.

`dms setup` writes the main config plus fragments under `~/.config/hypr/dms/`:

| Fragment | Purpose | Settings page |
| --- | --- | --- |
| `colors.lua` | Theme colors | Wallpaper & colors |
| `layout.lua` | Layout, gaps, borders, blur, effects, xray layer rules | System & integrations → Hyprland, Interface style (Blur strength) |
| `outputs.lua` | Monitors and display settings | Displays |
| `cursor.lua` | Cursor settings | Wallpaper & colors |
| `input.lua` | Mouse, touchpad and keyboard settings | Input → Mouse & touchpad, Keyboard |
| `binds.lua` | DMS-managed default shortcuts | - |
| `binds-user.lua` | Your shortcut overrides | Input → Keyboard shortcuts |
| `windowrules.lua` | Window rules | Applications → Window rules |

`binds.lua` is refreshed by `dms setup`, so put custom shortcuts in `binds-user.lua` or use the Keyboard Shortcuts page. Deleting a DMS default there saves an `hl.unbind("KEY")` line into `binds-user.lua` so the removal sticks across setup runs; **Reset to default** drops your override. Binds in your own `hyprland.lua` are read-only in Settings, DMS does not write files it does not manage.

Stock configs bind a 3-finger horizontal touchpad gesture to workspace switching (`hl.gesture` in `binds.lua`). Add your own `hl.gesture(...)` lines to `binds-user.lua` to change it, or drop a stock gesture with `action = "unset"` matching its fingers, direction, and modifiers.

#### Coming from hyprland.conf

Nothing is converted from a `hyprland.conf`. `dms setup` writes a fresh `hyprland.lua` and the `dms/*.lua` fragments, backing up any existing `hyprland.lua` to `~/.config/hypr/.dms-backups/<timestamp>/` first (including the stub Hyprland 0.57 autogenerates when it starts without a config). The old `hyprland.conf` is left in place and ignored.

Re-add shortcuts in `dms/binds-user.lua` or **Settings → Input → Keyboard shortcuts**, window rules in **Settings → Applications → Window rules**, and displays in **Settings → Displays**.

Check the result with:

```sh
dms setup
hyprctl reload
hyprctl configerrors
```

DMS applies colors, displays, layout, cursor, input, keybinds and window rules through the fragments above. `dms setup` adds these lines for you; if you maintain `hyprland.lua` by hand, keep them at the end in this order. ### Window Rules

```lua
-- Opacity for inactive windows
hl.window_rule({ match = { float = false, focus = false }, opacity = "0.9 0.9" })

-- GNOME apps
hl.window_rule({ match = { class = "^(org\\.gnome\\.)" }, border_size = 0, rounding = 12 })

-- Terminal apps - no borders
hl.window_rule({ match = { class = "^(org\\.wezfurlong\\.wezterm)$" }, border_size = 0 })
hl.window_rule({ match = { class = "^(Alacritty)$" }, border_size = 0 })
hl.window_rule({ match = { class = "^(zen)$" }, border_size = 0 })
hl.window_rule({ match = { class = "^(com\\.mitchellh\\.ghostty)$" }, border_size = 0 })
hl.window_rule({ match = { class = "^(kitty)$" }, border_size = 0 })

-- Floating windows
hl.window_rule({ match = { class = "^(gnome-calculator)$" }, float = true })

hl.window_rule({ match = { class = "^(blueman-manager)$" }, float = true })

hl.window_rule({ match = { class = "^(org\\.gnome\\.Nautilus)$" }, float = true })

-- Open DMS windows as floating by default (optional — DMS can manage this for you)
hl.window_rule({ match = { class = "^(dev\\.duxlabs\\.shell)$" }, float = true })
```

As on niri, **Settings → Interface style → Floating windows → Open floating** can manage this rule in `~/.config/hypr/dms/windowrules.lua` (click **Setup** on the banner if the fragment isn't included yet). DMS floating windows use app ID `dev.duxlabs.shell`.

#### Window rule editor

**Settings → Applications → Window rules** writes your rules to `~/.config/hypr/dms/windowrules.lua`. On Hyprland the editor adds:

- **Match**: Group and Modal toggles, plus an **Advanced Matching** card with Initial class, Initial title, Tag, XDG tag, Workspace, Content (none, photo, video, game), Fullscreen state, and Client fullscreen state. Prefix a tag with `negative:` to match windows without it.
- **Advanced** effects: No initial focus, Stay focused, Focus on activate, Confine pointer, No XDG drags, No glow (0.57+), No wobble (0.57+), No auto HDR, Tone mapping, scrolling Column Width, Border color, and Suppress events.

Corner radius goes up to 100 on Hyprland 0.57 and is capped at 20 on 0.55 and 0.56, which reject higher `rounding` values and drop the rule. Editing a rule keeps any fields the editor doesn't show.

### Compositor Settings (Hyprland)

**Settings → System & integrations → Hyprland** writes `~/.config/hypr/dms/layout.lua` and reloads Hyprland. DMS reads the running Hyprland's options once (`hyprctl -j descriptions`) and hides or skips anything your version doesn't have.

**Tiling layout**

| Layout | Options |
| --- | --- |
| Off | Leaves `general:layout` to your own config |
| Dwindle | Preserve split, Smart split, Force split (Follow mouse, Left, Right) |
| Master | Master position, New windows (Stack, Master, Inherit), New windows on top of the stack, Master size |
| Scrolling | Direction, Column Width, Fullscreen single column, Follow focus (Off, On, Not on click) |

**Not on click** (0.57+, `scrolling:follow_focus = 2`) lets focus changes move the tape but not clicks.

**Layout overrides**

- **Gaps**: Auto follows the bar spacing, Custom shows **Inner gaps** and **Outer gaps** sliders, Off leaves gaps to your config.
- **Window radius** follows **Interface style → Corners**.
- **Override border size**.
- **Resize on border**, with a **Border grab area** slider (`general:extend_border_grab_area`) for the extra space around borders that still starts a resize.
- **Window opacity** for app windows.
- **Center dragged windows** (0.57+, `binds:drag_center_window`): a tiled or fullscreen window dragged into floating centers on the cursor.
- **Xray blur** and **Bar xray** / **Frame xray**. See [Layer Namespaces](./layers.mdx#xray).

**Visual effects**

| Setting | Hyprland | Notes |
| --- | --- | --- |
| **Blur** style | 0.57+ | Default, Frost, Ripple, Drops, Water, Fluid jar, Prism, Heat shimmer, Acrylic, Aurora, Haze. See [Compositor Blur](./compositor-blur.mdx#hyprland-blur-styles) |
| **Blur follows opacity** | 0.57+ | More transparent areas get less blur (`decoration:blur:proportional`) |
| **Glow** | 0.55+ | Inner glow along window edges in the theme color, with range and **Glow falloff** sliders |
| **Wobbly windows** | 0.57+ | Intensity and **Wobble stiffness** sliders |
| **Motion blur** | 0.56+ | Sample count; more samples look smoother and cost more GPU |

Effects apply to every window, including DMS floating windows such as Settings and Notepad, which also wobble. Blur reach is the **Blur strength** slider under **Interface style**, not part of this card.

**Window groups**

**Background blur** for the group bar, **Title padding**, **Middle click closes**, and **Hide with one window** (0.56+). Options your Hyprland doesn't have are not written.

**Behavior**

| Setting | Hyprland | Notes |
| --- | --- | --- |
| **Workspace back and forth** | 0.55+ | Switching to the current workspace returns to the previous one (`binds:workspace_back_and_forth`). Off, All displays, or Per display (0.57+); Off or On on older releases |
| **Keep fullscreen on close** | 0.55+ | Closing a fullscreen window makes the next focused one fullscreen (`misc:exit_window_retains_fullscreen`). Off or On; Only in groups and Only outside groups on 0.57+ |
| **System bell** | 0.57+ | `misc:bell_sound`. Hyprland 0.57 plays a bell by default; Off writes an empty sound |

**Input and cursor**

These Hyprland rows live on other Settings pages and are hidden unless the running Hyprland has the option:

| Setting | Page | Hyprland | Notes |
| --- | --- | --- | --- |
| **Swallow focus click** | Input → Mouse & touchpad → Mouse | 0.57+ | The click that focuses a window does not reach the app (`input:swallow_focus_click`), written to `dms/input.lua` |
| **Tablet input** | Input → Mouse & touchpad → Tablet | 0.57+ | Turns drawing tablet input on or off (`input:tablet:enabled`), written to `dms/input.lua` |
| **Warp on display change** | Wallpaper & colors → Cursor | 0.57+ | Same as workspace change, Off, On, or Force (`cursor:warp_on_monitor_change`), written to `dms/cursor.lua` |

## MangoWC Configuration

[MangoWC](https://github.com/DreamMaoMao/mangowc) is a dynamic tiling Wayland compositor based on dwl (wlroots). Configuration lives at `~/.config/mango/config.conf`.

:::note[MangoWC 0.18 or newer]
MangoWC 0.18 renamed its config keys to snake_case and dropped the old names (`exec-once` is now `exec_once`, `windowrule` is `window_rule`, `monitorrule` is `monitor_rule`, `borderpx` is `border_px`, and so on). The file format is still `.conf`, not TOML. Lines with the old names are rejected as unknown keywords. DMS supports MangoWC 0.18 and newer, and everything `dms setup` and the shell write uses the snake_case names.

To convert an older config, run the `migrate-config-keys.sh` attached to [MangoWC's 0.18.0 release](https://github.com/DreamMaoMao/mangowc/releases/tag/0.18.0) over `~/.config/mango`; it rewrites `config.conf` and the DMS fragments alike. If you had that script running from a systemd `--user` path unit or a cron job to keep up with DMS, remove it: DMS writes snake_case itself now. [`dms doctor`](./cli-doctor.mdx#compositor-checks) lists any keys MangoWC still rejects.
:::

### Key Configuration Sections

`dms setup` writes the main config plus fragments under `~/.config/mango/dms/`:

| Fragment | Purpose | Settings page |
| --- | --- | --- |
| `colors.conf` | Theme colors | Wallpaper & colors |
| `layout.conf` | Gaps, borders, window radius, DMS layer rules | System & integrations → Compositor |
| `cursor.conf` | Cursor theme, size and hide timeout | Wallpaper & colors |
| `input.conf` | Mouse, touchpad and keyboard settings | Input → Mouse & touchpad, Keyboard |
| `outputs.conf` | Monitors and display settings | Displays |
| `windowrules.conf` | Window rules | Applications → Window rules |
| `binds.conf` | Keybinds | Input → Keyboard shortcuts |

If you maintain `config.conf` by hand, source every fragment and make sure the files exist. A **First Time Setup** banner on the matching Settings page adds a missing `source` line for you.

```conf
# Add to the end of ~/.config/mango/config.conf
source=./dms/colors.conf
source=./dms/layout.conf
source=./dms/cursor.conf
source=./dms/input.conf
source=./dms/outputs.conf
source=./dms/windowrules.conf
source=./dms/binds.conf
```

```bash
mkdir -p ~/.config/mango/dms
touch ~/.config/mango/dms/{colors,layout,cursor,input,outputs,windowrules,binds}.conf
```

Mouse and touchpad rows map onto MangoWC's `mouse_*` and `trackpad_*` keys. Keyboard keys (`xkb_rules_*`, `repeat_*`, numlock) are written only once you set one of them, so an untouched Keyboard page keeps the keyboard lines in your own `config.conf`. The **Keymap file** row is hidden on MangoWC because it has no such option. Numlock is written as `numlock_on`.

#### Layer Rules

DMS writes these rules into `dms/layout.conf`, so MangoWC skips its layer animation on the shell's own surfaces:

```conf
layer_rule=no_animation:1,layer_name:^(quickshell)$
layer_rule=no_animation:1,layer_name:^dms:.*
```

With `layer_animations=1`, MangoWC restarts a move animation every time a layer changes size or position, so the dot and island lag behind. If you do not source `dms/layout.conf`, copy these lines into `config.conf`. A `layer_rule=no_animation:1,layer_name:^dms` line you added by hand earlier can go.

Each matching `layer_rule` resets the on/off options it does not set, so the last match wins. Put your own rules for DMS layers after `source=./dms/layout.conf` and include `no_animation:1`. To let DMS layers animate instead, add the same two lines there with `no_animation:0`. MangoWC applies layer rules when a layer opens, so restart the shell once after updating (`dms restart`).

For more about layer rules see [layer rules](./layers.mdx).

## Other Compositors

Dux Shell works with any Wayland compositor that supports:
- Layer shell protocol (for panels and overlays)
- Session lock protocol (for lock screen)
- ext-workspace-v1 protocol (for workspace management)
- wlr-output-management-unstable-v1 protocol (for interface scaling + output management)

**Note:** Some compositor-specific features will be unavailable, such as workspace switching.

### Basic Integration

For other compositors, you need to:

1. **Auto-start DMS:**
   ```bash
   dms run
   ```

2. **Configure keybindings** using the IPC commands from the [Keybinds & IPC](keybinds-ipc) guide

3. **Set environment variables** in `~/.config/environment.d/90-dms.conf` (for systemd users) or your compositor config:
   ```ini
   QT_QPA_PLATFORM=wayland
   ```
   You can also use `systemctl --user edit dms` and add `Environment=QT_QPA_PLATFORM=wayland` under `[Service]`. This only affects DMS and apps it launches, whereas `90-dms.conf` applies to all user sessions.

### Example for Sway

Add to `~/.config/sway/config`:

```conf
# DMS Keybindings
bindsym $mod+space exec dms ipc call spotlight toggle
bindsym $mod+v exec dms ipc call clipboard toggle
bindsym $mod+m exec dms ipc call processlist focusOrToggle
bindsym $mod+comma exec dms ipc call settings focusOrToggle

# Audio controls
bindsym XF86AudioRaiseVolume exec dms ipc call audio increment 3
bindsym XF86AudioLowerVolume exec dms ipc call audio decrement 3
bindsym XF86AudioMute exec dms ipc call audio mute

# Brightness controls
bindsym XF86MonBrightnessUp exec dms ipc call brightness increment 5
bindsym XF86MonBrightnessDown exec dms ipc call brightness decrement 5
```

## Troubleshooting

### DMS doesn't start automatically

Check your compositor's logs to ensure the `spawn-at-startup` or equivalent startup command is running. You can also manually start DMS with `dms run` to see any error messages.

### Keybindings don't work

Verify that:
- DMS is running (`pgrep -f "dms run"`)
- Your keybinding syntax matches your compositor's format
